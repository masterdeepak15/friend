# Web video Implementation Plan

> For agentic workers: executed inline (executing-plans), TDD per task, tasks in order, one commit per task.

**Goal:** the assistant plays videos from YouTube and other sites, on the Friend screen (ffmpeg stream) or in a PC window (mpv).

**Spec:** docs/superpowers/specs/2026-10-12-web-video-design.md

**Architecture:** a `video/` server module (address vetting, yt-dlp resolver, ffmpeg stream, mpv window, hub with tokens), a signed-in
route `/api/video/:id`, three agent tools, a `video` plugin (integration) with settings and a Configure page, the existing stage video card.

## Global constraints
- Safety floors fixed in code (http/https only, public addresses only, no login in link, fixed yt-dlp/ffmpeg flags, caps); knobs are settings.
- The assistant cannot enable or configure the plugin (PIN only). Never installs the helper programs.
- Tests use injected fakes; no network in unit tests.

## Task 1: settings, protocol tools, plugin entry
Files: protocol `tools.ts` (+test), server `config.ts`, `settings.ts` (agent refused), `integrations.ts` (+`changeVideo`), `app.ts`, web `MEDIA_SRC`.
Produces: `Config.video: VideoConfig`, tools `video.play|video.control|video.check`, integration id `video`.

## Task 2: address vetting and the resolver
Files: `server/src/video/url.ts` (`vetVideoUrl(raw, {resolve, allowedSites}) -> {ok,url}|{ok:false,error}`), `video/tools.ts` (find yt-dlp / ffmpeg: `findProgram`), `video/resolve.ts` (`resolveVideo(input, deps) -> VideoInfo`).
Produces: `VideoInfo { id, title, uploader, durationSec, webpage, thumbnail, live, inputs: {url, headers}[] }`.

## Task 3: the ffmpeg stream and the hub
Files: `video/stream.ts` (`startStream(info, {startSec, maxHeight}, deps) -> {stdout, stop()}`), `video/hub.ts` (`VideoHub`: `play`, `control`, `check`, `streamOf(id)`, tokens with TTL, cap).
Produces: `VideoHub.play({url?, query?, output?, start?}) -> {ok, summary, id?}`.

## Task 4: the PC window
Files: `music/mpv.ts` (`mode: "video"` args), `video/host.ts` (`VideoHost`: open, pause, resume, seek, volume, stop, state).

## Task 5: route, agent tools, policy, prompt
Files: `gateway.ts` (`GET /api/video/:id`), `agent/loop.ts` (execute the three tools; screen output shows a stage `video` card), `policy/engine.ts`, `alexa/constants.ts`, `agent/prompt.ts`.

## Task 6: the plugin page and the video card
Files: web `plugins/VideoForm.tsx` (helper check, output, quality), `IntegrationConfig.tsx`, `objects/more.tsx` (message when a stream fails), tests.

## Task 7: docs, live check, release
README bullet, `docs/guides/web-video.md`, live check with the real programs, version bump and publish only when asked.
